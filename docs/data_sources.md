# Data sources

* **Primary: Financial Modeling Prep** (`FMP_API_KEY` env var; never commit it).
  * Daily: `stable/historical-price-eod/full` (split-adjusted, dividend-unadjusted = raw, like Dynamic Trader). Weekly bars are resampled from daily (Monday-labelled, same as Yahoo).
  * Intraday: `stable/historical-chart/{15min,30min,1hour}`. FMP returns newest-first with a per-call cap, so the server fetches fixed epoch-aligned calendar chunks (15m: 30d, 30m: 25d, 60m: 80d) in parallel, pages backwards inside a chunk if truncated, and caches past chunks for 6 h (live chunk 60 s). Times are US/Eastern; stocks/indices keep 9:30–16:00 only, futures keep the full Globex session, crypto is converted to UTC.
  * Max intraday lookback: `MAX_15M` (default `1y`), `MAX_30M` (`2y`), `MAX_60M` (`3y`).
  * Symbols: Yahoo-style aliases are kept (SPX→^GSPC, ES→ES=F …); futures map to FMP continuous symbols (ES=F→ESUSD, NQ=F→NQUSD, …), crypto BTC-USD→BTCUSD.
* **Fallback: Yahoo Finance (yfinance)** when no key is set, FMP errors, or FMP has no data for the symbol. Yahoo limits: 15m/30m ≈ 60 days, 60m ≈ 730 days (longer requests are clamped).
* `DATA_SOURCE=auto|fmp|yahoo` (default `auto`). `/api/history` and `/api/pivots` report `"source"`; the status bar and chart footer show it.

## IPO offer price (IPO grid overlay)

`GET /api/ipo?symbol=XYZ` → `{found, offer, ipoDate, splitFactor, adjustedOffer, source, confidence, filingUrl, filingDate, form, splits[], message}` (200 with `found:false` and a `message` when nothing usable is found; `eligible:false` for futures/indexes/FX/crypto). Cached in memory (found 7 d, not found 1 h, errors never).

* **First-trade date:** FMP `stable/profile` → `ipoDate` (else the first daily bar if the history is not truncated at FMP's 5000 rows).
* **Offer price (1st): FMP `stable/ipos-prospectus`.** The endpoint ignores `symbol`, `limit` and `page` and filters by *filing* date, so the server fetches a ±10-day window around the first-trade date and matches the symbol. Only final-prospectus forms (`424B4`, `424B1`) are used; the `S-1`/`S-1/A` rows in the same feed carry range/placeholder prices (ABNB S-1/A 6.77, DASH S-1/A 8.73). Never use `ipos-calendar` `priceRange`.
* **Offer price (2nd / cross-check): SEC EDGAR** (free, no key, public domain). Needs `SEC_USER_AGENT="Name contact@email"` (SEC fair-access policy; requests without a contact are blocked, max 10 req/s — the server throttles to ~5/s). `files/company_tickers.json` → CIK → `data.sec.gov/submissions` → the 424B4/424B1 (424B2/424B3 only if none) filed within −3/+7 days of the first-trade date → cover-page price parsed from the filing. Covers filings from 1994 on and current tickers only (a company that changed CIK, e.g. Google 2004 → Alphabet 2015, is not found).
* **Reconciliation:** if FMP and EDGAR both have a price and disagree, the filing's cover page wins and `fmpOffer` reports FMP's value (FMP's `pricePublicPerShare` is sometimes the net proceeds or a parse error: META 37.58 vs 38.00, ZM 34.2 vs 36, LYFT 20.71 vs 72, SNOW 240486119 vs 120). Without `SEC_USER_AGENT` an FMP-only price is marked `single source (FMP only…)` and shown as "unconfirmed" in the UI.
* **Sanity check:** the split-adjusted offer must be within 0.2×–5× of the first-day open, else it is rejected (FMP lists PLTR's direct listing as 737).
* **Splits:** `stable/splits?symbol=X`; `adjustedOffer = offer / Π(numerator/denominator)` for splits dated after the first-trade date (reverse splits work the same way). FMP/Yahoo daily bars are split-adjusted but dividend-unadjusted, the same basis as the offer price.
* **Not covered:** IPOs before ~1994 (AAPL 1980, MSFT 1986, ORCL 1986, CSCO 1990 → "No IPO data" + manual box), direct listings/SPAC mergers (no offer price), spin-offs. Not used: Nasdaq `api.nasdaq.com` (works for 1997+, but Nasdaq's terms forbid automated capture), StockAnalysis (2019+ pages, Cloudflare challenge), Renaissance Capital (paid API, no scraping), IPOScoop (paid feed).

**Futures / indexes / FX / crypto (GC=F, ES=F, ^GSPC, EURUSD=X or bare EURUSD, BTC-USD …):** no IPO exists, so `/api/ipo` is not called (it answers `eligible:false`). The toolbar box becomes "Base $": type the base price (e.g. GC 35 → lines at 35, 52.5, 70 …, and 17.5 with "Below"). The value is used exactly as typed (not split-adjusted — enter it on the chart's displayed, possibly continuous-contract, price scale), stored per normalized ticker (`ftpIpo:GC=F`, so `GC` and `GC=F` share it; `SPX` = `^GSPC`, `BTC` = `BTC-USD`), and typing a value switches the grid on. No "No IPO data" notice is shown for these tickers.
